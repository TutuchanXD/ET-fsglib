# 调试输出与误差分解说明

## 1. 输出目录

当前单帧调试输出默认保存在：

- `/home/cxgao/ET/FSG/fsglib/outputs/debug`

每个输入帧会生成一个同名 bundle，例如：

- `/home/cxgao/ET/FSG/fsglib/outputs/debug/scope0_coadd_000000_000000`

## 2. 每个 bundle 中的文件

- `raw.npy`
  - 原始图像数组。
- `preprocessed.npy`
  - 预处理后的图像数组。
- `noise_map.npy`
  - 预处理阶段估计的噪声图。
- `truth_stars.json`
  - 来自 `stars.ecsv` 的静态真值星表，已转换到像素坐标。
- `reference_stars.json`
  - 当前帧构造出来的参考星，以及其预测像点。
- `candidates.json`
  - 星点提取阶段输出的候选质心。
- `matches.json`
  - 最终参与姿态解算的匹配对，包含 truth / predicted / observed 三类信息。
- `solution.json`
  - 本帧主结果。
- `analysis.json`
  - 对误差来源做进一步分解后的结果。
- `overlay_truth_candidates.png`
  - 静态 truth 与提取质心叠加图。
- `matched_truth_bias.png`
  - matched 星从静态 truth 指向观测质心的偏差矢量图。
- `matched_prediction_overlay.png`
  - 参考预测像点指向观测质心的残差矢量图。
- `README.md`
  - 当前 bundle 的快速说明。

## 3. `solution.json` 主要字段

- `valid`
  - 本帧姿态解是否通过当前门限。
- `num_matched`
  - 进入姿态解算的匹配星数。
- `num_rejected`
  - 姿态求解阶段剔除的星数。
- `q_ib`
  - 四元数 `[w, x, y, z]`，表示惯性系到本体系的旋转。
- `residual_rms_arcsec`
  - 姿态解算后，matched 星方向矢量残差的 RMS，单位角秒。
- `residual_max_arcsec`
  - 姿态解算后最大方向残差，单位角秒。
- `quality_flag`
  - 当前质量标签。
- `degraded_level`
  - 当前解算的降级等级。
- `active_detector_ids`
  - 当前参与解算的探测器编号。
- `solver_iterations`
  - 求解器迭代次数。
- `quality`
  - 姿态解算的质量摘要，如输入星数、使用星数、残差门限。
- `timings_s`
  - 各阶段耗时。
- `matching.debug.mean_residual_pix`
  - 匹配阶段中，预测像点到观测质心的平均像面残差。
- `evaluation.centroid_mae_pix`
  - 提取质心到静态 `stars.ecsv` 的平均最近邻距离。
- `evaluation.non_roll_error_arcsec`
  - 非绕光轴姿态误差。
- `evaluation.roll_error_arcsec`
  - 绕光轴姿态误差。
- `evaluation.total_attitude_error_arcsec`
  - 总姿态误差角。

## 4. 误差分解的正确读法

当前需要特别注意的一点是：

- `stars.ecsv` 是静态 truth。
- 仿真图像中实际渲染的星点，可能已经叠加了逐帧的 `DVA / pointing drift / thermal drift`。

因此：

- `evaluation.centroid_mae_pix`
  - 不能直接视为“纯质心算法误差”。
  - 它混合了静态 truth 与逐帧动态图像之间的公共平移项，以及局部质心误差。

更合理的读法是看 `analysis.json` 中的两层分解。

### 4.1 `candidate_vs_static_truth`

这是“所有提取候选”相对静态 truth 的最近邻比较。

- `mean_dx_pix / mean_dy_pix`
  - 表示整帧相对静态 truth 的公共平移项。
- `mean_shift_mag_pix`
  - 公共平移量的模长。
- `radial_error_stats`
  - 未去除公共平移时的总误差。
- `after_common_shift_radial_error_stats`
  - 去掉公共平移后的局部散布，更接近真正的局部质心误差。

### 4.2 `matched_truth_alignment`

这是“进入姿态解算的 matched 星”相对静态 truth 的比较。

- 匹配关系不是靠像面最近邻，而是靠 RA/Dec 惯性方向最近邻建立。
- 相比 `candidate_vs_static_truth`，它更适合判断：
  - 当前主导项是整帧公共平移，还是局部散布。

如果这里看到：

- `mean_dx_pix / mean_dy_pix` 很大；
- 但 `after_common_shift_radial_error_stats.rms` 明显更小；

那么说明当前大误差更多来自“整帧公共位移”，而不是每颗星都随机漂得很厉害。

### 4.3 `match_prediction_residual`

这是匹配阶段真正使用的：

- 参考预测像点 `predicted_xy`
- 观测质心 `observed_xy`

之间的残差。

它更接近“当前参考星构建 + 当前图像定位 + 当前匹配”组合后的像面闭环误差。

## 5. 当前推荐分析顺序

建议按下面顺序看单帧结果：

1. 看 `overlay_truth_candidates.png`
   - 判断提取质心整体是否相对静态 truth 出现系统平移。
2. 看 `matched_truth_bias.png`
   - 判断 bias 向量是否大致同向。
3. 看 `analysis.json`
   - 先看 `candidate_vs_static_truth.mean_shift_mag_pix`
   - 再看 `matched_truth_alignment.after_common_shift_radial_error_stats.rms`
4. 最后看 `solution.json`
   - 判断这部分像面误差最后如何传播到 `non_roll / roll / total attitude error`

## 6. 当前代码口径下的重要提醒

- 当前主探测器 `v2` 数据口径下，静态几何投影已经与仿真基本对齐。
- 当前仍需重点区分两类误差：
  - 图像相对静态 truth 的公共平移项；
  - 去掉公共平移后剩余的局部质心与匹配误差。
- `roll` 误差不能只通过看 `centroid_mae_pix` 判断，需要结合 matched 星的空间分布和系统性偏差一起分析。
