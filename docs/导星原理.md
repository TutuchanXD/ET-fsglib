# 导星原理与 `fsglib` 实现说明

## 1. 目的

本文档用于同时维护两件事：

1. 导星算法本身的理论链条是否正确；
2. 当前 `fsglib` 代码究竟实现到了哪一步、哪些地方仍是简化或待补齐项。

这份文档不是替代参考开发文档，而是把“导星原理”和“当前代码实现”直接对齐。

---

## 2. 先回答核心问题

你的理解是对的，但工程上最好把链条再说得更精确一点。

高层上，导星链路确实可以理解成：

1. 从探测器图像平面提取星点位置；
2. 把像面位置变成导星坐标系下的方向矢量；
3. 再和天球坐标系中的参考星方向矢量做匹配与姿态解算。

但在实现层，通常不是“3 个坐标系一步到位”，而是下面这条更完整的链：

1. 图像像素坐标 / 像面坐标
2. 光学视场角坐标
3. 导星仪本体系方向矢量
4. 天球惯性系方向矢量

也就是说：

- 图像端负责把星点从“像素位置”提出来；
- 投影模型负责把“像素 / 像面位置”变成“本体系 LOS”；
- 星表 / 星历模块负责给出“惯性系 LOS”；
- 匹配与姿态解算模块负责把这两类 LOS 对齐。

---

## 3. 三层核心坐标链

### 3.1 像面坐标

这是探测器图像上的星点位置。

在当前 `fsglib` 中，它体现为：

- 提取后的星点质心 `(x, y)`，单位是 pixel
- 对主探测器 `v2` 数据来说，主点约在 `(559, 559)`

这一步回答的问题是：

> 星在图像上落在哪个像素位置？

当前代码对应：

- `preprocess/pipeline.py`
- `extract/pipeline.py`

### 3.2 视场角 / 光学投影坐标

这是光学中间层。

它回答的问题是：

> 这个像面点对应哪一个视场方向？

如果是理想 pinhole 或当前 `v2` 这种小视场线性模型，可以把它看成：

- `x_pix -> FOV_X`
- `y_pix -> FOV_Y`

如果未来接入真实光学畸变，就需要：

- 像面毫米坐标
- 三次畸变模型或 LUT
- 每片探测器独立主点 / 安装矩阵 / 可见边界

当前代码对应：

- `ephemeris/projector.py`

### 3.3 导星仪本体系方向矢量

这是姿态解算真正使用的观测量。

它回答的问题是：

> 在导星仪本体系里，这颗星的观测方向矢量是什么？

形式上通常记为：

- `los_body`

也就是单位方向向量：

```text
los_body = [bx, by, bz], ||los_body|| = 1
```

当前代码对应：

- `pipeline/convert.py`
- `common/types.py` 中的 `ObservedStar.los_body`

### 3.4 天球惯性系方向矢量

这是参考星表给出的理论真值方向。

它回答的问题是：

> 在惯性系 / 天球坐标系里，这颗参考星的方向矢量是什么？

形式上通常记为：

- `los_inertial`

它来自：

- Gaia 星表的 `RA/Dec`
- 必要时加上 proper motion / parallax / DVA / relativity 等修正

当前代码对应：

- `ephemeris/catalog.py`
- `ephemeris/pipeline.py`
- `common/coords.py`

## 4. 姿态解算真正解的是什么

姿态解算不是直接“从像素到姿态”。

它实际解的是：

> 找到一个旋转，使观测方向矢量 `los_body` 和参考方向矢量 `los_inertial` 最一致。

也就是求一个旋转矩阵 / 四元数：

```text
C_ib or q_ib
```

使得：

```text
los_body ≈ C_ib * los_inertial
```

这里：

- `i` 表示惯性系
- `b` 表示导星仪 / 本体系

所以导星算法本质上是一个“观测矢量集合”和“参考矢量集合”的对准问题。

当前代码对应：

- `attitude/solver.py`

## 5. 当前 `fsglib` 主链路是怎么做的

### 5.1 图像到候选星点

当前流程：

1. 全局中值做背景扣除
2. 全局标准差估计噪声
3. 用 `SNR > seed_threshold_sigma` 做阈值检测
4. 对连通域做加权质心

当前实现特点：

- 这是一个很简化的质心法
- 没有局部背景
- 没有 PSF 拟合
- 没有亚像元模板
- 没有饱和 / 邻星去混叠的复杂处理

因此它更像一个第一阶段可运行基线，而不是最终高精度星点定位器。

### 5.2 像面到本体系 LOS

当前 `v2` 主探测器链路使用：

- `sky_patch_linearized`

也就是：

- 用批次中心 `RA/Dec` 建立局部切平面
- 像素偏移经比例尺换成小角度
- 小角度再转成本体系 LOS

对当前新 `v2` 仿真，静态几何已经验证对齐到 `1e-11 pix` 量级。

这说明：

- 当前 `v2` 的主问题不在“静态投影公式写错”
- 后续误差排查应更多关注图像端和逐帧运动建模

### 5.3 天球参考星生成

当前做法：

1. 从 Gaia healpix 库查局部参考星
2. 对 `v2` 调试模式，按可见矩形视场筛选
3. 用与仿真端一致的 `Gaia G -> Kepler Mag` 近似
4. 裁到最亮 `200` 颗参考星

这一步主要保证“参考星集合口径”和仿真端一致。

### 5.4 匹配

当前主线是：

- `init`：基于当前粗姿态生成参考星并做局部位置匹配
- `tracking`：基于上一帧姿态预测参考星位置，再做近邻匹配

当前 `tracking` 的匹配器本质上是：

- predicted position nearest-neighbor

这对调试足够，但还不是最终鲁棒识别器。

### 5.5 姿态解算

当前求解器本质上是：

- Wahba / SVD 解

接口是按后续 QUEST 形态整理的，但还没有严格 QUEST 实现。

## 6. 当前仿真端与 `fsglib` 的对齐状态

### 6.1 已对齐的部分

#### 星源

- 仿真端与 `fsglib` 使用同源 Gaia 星源
- 当前 `v2` 的参考星筛选口径也已与仿真端主流程对齐

#### 静态几何

- 新 `v2` 已关闭静态 field offset
- `run_meta.json` 已显式记录 `field_offset_x_pix = field_offset_y_pix = 0`
- `fsglib` 回投 `stars.ecsv` 静态几何误差约 `1e-11 pix`

#### 当前主探测器畸变口径

对这批 `v2` 来说，当前实际运行的是线性小视场模型，不是 Zemax 畸变模型。

因此：

- 仿真端：当前主探测器近似无畸变
- `fsglib`：`main_sim_v2` 也不启用畸变投影

这两者是对齐的。

### 6.2 尚未对齐的部分

#### DVA

仿真端：

- 明确加入了 `DVA drift`
- 并且当前脚本确实在启用

`fsglib`：

- 配置里有 `enable_dva`
- 但当前运行链路没有真正实现 DVA 修正

所以这部分目前并不对齐。

#### 逐帧真值

当前仿真输出：

- `stars.ecsv` 只给静态星位
- `.npz` 不带逐帧星位真值

但图像里真实还叠加了：

- DVA
- pointing drift
- jitter
- thermal drift

所以静态 `stars.ecsv` 不能被当成“逐帧最终 truth”。

#### 星点定位模型

仿真端图像包含：

- PSF
- jitter integration
- detector response
- 多种噪声

而当前 `fsglib` 提取器只是简单加权质心。

这也是当前精度差距的主要来源之一。

## 7. 为什么质心误差必须单独审计

姿态误差不是凭空长出来的。

最常见的传播路径是：

```text
像面质心误差
-> 观测 LOS 误差
-> 匹配 / 权重 /几何约束误差
-> 最终姿态误差
```

因此你提的这个问题是完全正确的：

> 必须先确认误差是不是在“质心提取”这一步就起来了。

当前阶段至少要同时看两类误差：

1. 候选质心相对静态 truth 的误差
2. matched 星点相对 truth 的误差

其中第 1 类更适合看：

- 提取器本身是否足够精

第 2 类更适合看：

- 匹配后真正参与姿态解算的点，其误差场是什么样

尤其要分解成：

- 径向误差
- 切向误差

因为：

- 非绕光轴误差更容易和径向 / 整体平移相关
- 绕光轴误差往往对低幅但有组织的切向偏差更敏感

需要强调的是：

在小视场上，即使只有很小的系统性切向偏差，也可能转成很多角秒的 `roll` 误差。

## 8. 当前对 `batch2 / batch3` 的初步判断

### 8.1 `batch2`

更像是“整体星点定位质量差”主导。

目前现象：

- matched truth 的径向 / 切向 RMS 都明显偏大
- 首帧 `roll` 也很差

这说明它不只是某一个单独分量有问题，而是整体像面定位误差场都在变差。

### 8.2 `batch3`

不是简单的“切向 RMS 更大”。

目前现象：

- matched truth 的径向 / 切向 RMS 与 `batch0/1` 更接近
- 但 `roll` 仍明显偏大
- 匹配星的空间覆盖和几何条件数也不算极端

因此当前不优先怀疑：

- 静态几何
- 明显的星场构型退化

而更像是：

- 更微弱但有组织的姿态分量偏差
- 或某种未显式建模的逐帧运动 / 图像端系统误差

---

## 9. 当前代码中的关键简化

为了避免误解，下面这些点要明确记录：

1. `main_sim_v2` 当前不是严格真实导星仪光学模型，而是主探测器仿真验证口径
2. 当前姿态解算器还不是严格 QUEST，而是 SVD/Wahba 最小可用版本
3. 当前 `enable_dva` / `enable_relativity` / `enable_proper_motion` 等修正开关还没有真正进入运行链路
4. 当前 `stars.ecsv` 是静态 truth，不是逐帧 truth
5. 当前质心算法只是第一版加权质心，不应被误认为已达到最终精度设计

---

## 10. 建议的后续推进顺序

按当前状态，最合理的顺序是：

1. 继续拆 `batch2 / batch3` 的质心误差场和姿态分量误差
2. 明确判断一阶加权质心是否已经到瓶颈
3. 若是，则引入更高精度的 centroid / PSF-aware 方法
4. 同时规划逐帧 truth 导出或 DVA 显式修正接口

只有这样，后面看到的姿态精度变化才有明确归因。
